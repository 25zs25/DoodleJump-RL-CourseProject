## 模块目标与结论

本模块把普通开源游戏转化为可重复交互的强化学习环境，负责环境边界、随机种子、结构观测、奖励和数值一致性。训练侧可以高速运行，浏览器仍执行原版脚本、图片与绘制函数。核心结论是：当前声明窗口和测试覆盖范围内，原 JavaScript、浏览器适配层与 Python 移植的状态演化相符；这种验证不代表所有窗口、所有地图或商业官方游戏都已经得到等价证明。

本报告描述对应模块的技术成果、实现依据与验证方法。模块编号表示分工范围；实际参与的实现、复核、实验和写作工作由成员在末页据实填写。项目结果来自已保存的配置、权重与逐局记录。

## 原版来源与保留边界

上游为 takosenpai2687/doodle-jump，固定提交 d4b6071813a9c1353267d53dcfa9d8abc3e5b2f4。upstream 保存 21 个原文件，使用 upstream_manifest.json 逐个核对 SHA256。增加的 bridge-core.js 和 ui-bridge.js 位于原脚本之外，包装 reset、step、种子、观测和指标，不替换原碰撞或平台生成函数。

平台横坐标仍在全宽独立抽样。刷新时的类型抽样为 50% 普通、20% 移动、30% 易碎；初始层拒绝易碎，刷新易碎层时另补普通平台，因此实际总体类型比例不等于这三个抽样比例。弹簧抽样概率为 0.1，黑洞按原条件出现。环境没有加入保证任意地图可解的约束。

## 环境接口

| 接口 | 输入与输出 |
| --- | --- |
| reset(seed) | 用地图种子重置，返回 209 维 float32 观测 |
| step(action) | 动作 0、1、2 为左、不动、右；保持最多 4 个物理帧 |
| 交互返回 | 下一观测、奖励、terminated、truncated、指标字典 |
| 原版终止 | 跌落或撞黑洞；死亡后必须重置 |
| 训练时限 | 1500 次决策，为截断；手动试玩不受此时限限制 |

同一张随机地图要求相同窗口、随机种子和随机调用顺序。仅种子相同但适配代码或窗口不同，不能保证同一地图。

## 随机源与物理移植

地图随机源是 32 位线性同余生成器：state←(1664525×state+1013904223) mod 2^32；random=state/2^32。只在原 setup、reset 和 draw 调用内临时替换 Math.random，并在调用后恢复。策略动作采样使用独立随机源，避免算法采样消耗平台随机序列。可控种子替代随机源但不改原抽样公式；它用于复现相同条件下的轨迹。

Python 移植保留原参数缩放、直接横向速度、下降时 1.33 倍重力、最大下落速度、普通和弹簧弹跳、横向超界直接绕屏，以及先碰撞再移动的顺序。画布 683×871 对应实际原窗口，参数由原 windowResized 规则得到。窗口变化会改变相对尺度，不能先固定旧尺寸再靠 CSS 缩放模拟新物理。

## 不寻常行为也属于实验环境

原 draw 的 forEach 固定初始迭代长度，但循环中 splice 与 push 会改变数组，移植必须按原索引顺序处理，不能改成先删除再批量生成。弹簧碰撞调用虽然传入弹簧尺寸，原 checkCollision 实际采用平台常量尺寸。出生位置取倒数第二个平台，固定阈值 300 可能在初帧把角色夹到下方。这些行为没有作为性能优化被修复。

## 209 维输入的精确定义

| 对象与维数 | 字段顺序与精确定义 |
| --- | --- |
| 玩家 5 维 | 2x/W-1；y/H；vx/speed；vy/superjump；(spawn_y-y+scroll-maxheight)/H |
| 平台 20×10 维 | 绕屏相对横坐标/W；相对纵坐标/H；平台宽度/W；移动平台 vx/2；普通、移动、易碎三种 one-hot；弹簧存在；弹簧相对平台中心的横向偏移/W；平台有效标记 |
| 黑洞 4 维 | 绕屏相对横坐标/W；相对纵坐标/H；碰撞半径 30/W；黑洞有效标记 |


W、H 是画布宽高，scroll 是累计滚屏距离，maxheight 是历史最高攀升。玩家第 5 项是当前攀升与历史最高的差值，而不是绝对高度。平台按 abs(platform_y-player_y) 排序；只取当前可见范围及边缘缓冲中的对象，最多 20 个，缺槽填 0。黑洞缺失时 4 项填 0。三类型标记分别对应原版 type=5、2、3。弹簧偏移是相对平台中心的位置，不能误写为绝对横坐标。

观测没有未来平台、随机状态或目标动作。无记忆 MLP 只接受局部结构信息，因此采用的是部分可观测控制的近似。历史最高相关字段不使它成为完整 Markov 状态；也不能称为从屏幕像素端到端学习。

## 奖励与最高攀升指标

每次决策奖励为 r=(score_next-score_current)/100-0.001-I(死亡)。正项鼓励获得原版分数，固定负项抑制无收益拖延，死亡扣 1。奖励是优化目标，浏览器显示的原版 score 仍是原游戏指标，二者不能直接混称。

原 score 在滚屏处理平台时逐个平台加一，不等于像素高度，也不是只在成功落台时加分。最高攀升按 max(0, spawn_y-y+scroll) 的历史最大值记录；spawn_y 保留真实初始位置，避免把初帧阈值夹取误算为正向攀升。它不修改物理，只作为辅助指标。

## 对训练结果的解释

当前窗口 Double DQN 得分 18584.2±1969.7，平均最高攀升 3744.3 px；DQN 得分 18476.5±1145.6。高分与攀升不相同，地图和出生行为也可能影响控制。当前结果不能单独归因某一物理因素，因为未做对应的独立因果消融。将地图改为保证可解或改动出生规则，应产生新环境版本并重新训练、评测。

## 交付与可复现验收

核心文件为 env.py、viewport.py、bridge-core.js、ui-bridge.js、upstream_manifest.json 与 PROVENANCE.md。tests/oracle.cjs 直接执行冻结原 JavaScript 作为对照；tests/verify_original.py 负责原版保留检查。验收先确认原文件哈希，再声明窗口和地图种子，最后比对完整状态轨迹。

独立复核时，应在不修改原版文件的前提下使用新动作序列和地图种子。如果发生分叉，先区分参数缩放、随机调用、循环突变和浮点顺序，而不是直接调整平台距离。核对结束原因时同时记录 terminated 与 truncated，防止时限被当作死亡。

实验依据：experiments/native_retrain_20261008/protocol.json；results/native_v2/summary.json；VERIFICATION.json。当前报告对应 native-viewport-v2，主窗口 683×871。
