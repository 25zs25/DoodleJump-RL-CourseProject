## 模块目标与结论

本模块实现 PPO 策略优化和 GAE 优势估计，并通过重新训练比较速度特征是否带来可见收益。完整观测 PPO 当前窗口得分 3944.8±535.6，速度置零为 4052.2±184.4；有限种子下没有得到“速度输入必然更优”的证据。PPO 在本轮预算和配置下明显弱于两个价值算法，这个结果描述本任务，不代表算法的普遍排序。

本报告描述对应模块的技术成果、实现依据与验证方法。模块编号表示分工范围；实际参与的实现、复核、实验和写作工作由成员在末页据实填写。项目结果来自已保存的配置、权重与逐局记录。

## 策略和价值网络

输入为 209 维局部结构观测。两层 128 单元骨干经 ReLU 后连接三动作策略头和标量价值头。策略头产生 logits，经 softmax 转为动作概率；训练按概率采样。价值头估计当前策略的折扣回报，用作优势基线，减少策略梯度波动。

| 网络部分 | 参数量 |
| --- | --- |
| 共享 209→128→128 骨干 | 43392 |
| 3 动作策略头 | 387 |
| 标量价值头 | 129 |
| 训练网络合计 | 43908 |
| 浏览器只导出骨干和策略头 | 43779 |

PPO 训练参数比 DQN 多 129 个，来自价值头；浏览器部署只需要策略动作。它使用当期采样批次进行若干轮更新，没有把旧批次放入 DQN 式长期经验回放。

## 结构观测消融的范围

完整输入包括玩家速度和移动平台速度。速度置零把玩家 vx、vy 与平台 vx 特征置为 0，仍保留位置、类型、弹簧、有效标记和其他信息；输入维数与网络参数量不变。每个消融模型从头训练，不能拿训练后的完整模型临时屏蔽特征冒充训练消融。

## PPO 目标与反向更新

动作概率比 ratio=pi_new(a|s)/pi_old(a|s)。截断目标为 min(ratio×A, clip(ratio,1-0.2,1+0.2)×A)，对其期望取负构成策略损失。这里 clip 不直接限制两个策略的精确 KL，也不是把所有参数更新统一截断。

总损失包含策略项、系数 0.5 的价值项和系数 0.01 的熵奖励项，实际实现还使用优势标准化与价值裁剪。前向计算当前 logits 与价值，求损失后反向传播共享骨干和对应头，梯度范数上限为 0.5，再由 Adam 更新。原游戏规则没有参与梯度计算。

## GAE 与时限边界

TD 残差 delta_t=r_t+gamma×(1-terminal_t)×V(s_next)-V(s_t)。优势为同一回合内各后续残差按 (gamma×lambda)^k 加权。gamma=0.99，lambda=0.95。这里必须区分是否 bootstrap 与是否延续递推。

死亡时下一价值为 0；时间截断时使用截断前最后观测的价值。任何回合重置都停止优势跨回合传播，防止新的出生状态回报流入上一回合。回报目标由 A+V 构造。tests/test_agents.py 独立数值例子检查死亡、截断保留 bootstrap 以及 GAE 递推的重置边界。

| 超参数 | 固定设置 |
| --- | --- |
| 并行环境与 rollout | 8；每环境 128 步 |
| 更新轮数与 minibatch | 4；256 |
| gamma 与 GAE lambda | 0.99；0.95 |
| 学习率与 clip | 0.0003；0.2 |
| 熵与价值系数 | 0.01；0.5 |
| 梯度范数、优势和价值 | 0.5；优势标准化；价值裁剪 |
| 预算 | 完整观测 3 次+速度置零 3 次，各 100 万决策 |

三算法按决策数对齐，并不意味着梯度更新次数、数据复用或计算量相等。PPO 的精确 rollout 数和最终预算以日志为准。

## 完整观测和部署口径

主测试统一使用 argmax 动作，保证与 DQN、Double DQN 的浏览器部署比较口径一致。训练的概率采样和评测的确定性动作是不同策略执行方式，因此另对相同 PPO 权重进行采样测试，而不替换主结果。

| 当前窗口 PPO 执行方式 | 得分 ± 种子 SD | 平均最高攀升 px |
| --- | --- | --- |
| argmax 主结果 | 3944.8 ± 535.6 | 688.5 |
| 按概率采样诊断 | 3576.4 ± 253.7 | 614.6 |

验证地图为 10000-10019；主测试为 61000-61099。每算法 3 个训练种子各评测 100 张地图，按种子均值统计 SD。验证选择 best.pt 后冻结权重，不按测试集结果继续调参。

## 速度置零的实际结果

| 场景 | 完整观测得分 ± SD | 速度置零得分 ± SD |
| --- | --- | --- |
| native 683×871 | 3944.8 ± 535.6 | 4052.2 ± 184.4 |
| desktop 596.25×1060 | 3021.7 ± 283.6 | 2683.1 ± 352.4 |
| mobile 390×844 | 3726.1 ± 188.7 | 3518.9 ± 444.2 |

原窗口置零均值高 107.5 分；其余两个场景的排序相反。速度有利于理论上的落点预测，但当前三种子优化、无记忆观测和奖励条件下不保证增加速度特征一定改善分数。没有足够重复与因果诊断支持“速度无用”或“速度必需”的结论。

窗口沿用原缩放规则，会改变布局、平台层数和阈值相对位置。跨窗口分数不是统一难度单位，不能仅凭这张表把差值归为泛化能力。未来时序观测、更多训练种子或高度奖励均应先固定新协议，再使用新保留测试。

## 代码交付与复核方法

agents.py 的 ActorCritic、generalized_advantages、ppo_update 是核心实现，train.py 管理并行采样和更新。六组 native_v2_ppo 模型目录保存配置、验证曲线、训练状态、best/final 权重和日志。检查 checkpoint metadata 的 observation 字段，可区分 full 与 no_velocity。

复核时首先检查 GAE 的 terminal mask 与 episode reset mask 是否分开，再检查最后下一状态确属截断前状态。重新运行消融应保持相同维数、种子计划和预算；修改多个输入组会使消融问题改变。浏览器输出数值和动作的对照验证导出正确性，不单独证明训练优化已经充分收敛。

实验依据：experiments/native_retrain_20261008/protocol.json；results/native_v2/summary.json；VERIFICATION.json。当前报告对应 native-viewport-v2，主窗口 683×871。
